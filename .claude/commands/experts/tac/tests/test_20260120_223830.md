## Prompt 1: Tactic Question (Basic)

**Question**: What is Tactic #3 - Template Your Engineering?

**Response**:

### Tactic #3: Template Your Engineering

> When you template your engineering, you encode your engineering workflows and best practices into reusable, scalable units of agentic success.

**Core Truth**: Plans are scaled prompts. Success is planned. Templates enable you to solve entire CLASSES of problems, not just individual problems.

**Key Concepts**:

1. **Templates Solve Problem Classes**
   - Create templates for chores, bugs, features, and refactors
   - Works consistently across small to large codebases
   - One template handles an entire category of work

2. **Meta-Prompts: Prompts That Build Prompts**
   - A meta-prompt is a prompt that builds another prompt
   - Your agent fills out the template based on your high-level description
   - From one line → comprehensive plan

3. **All Plans Written to `specs/` Directory**
   - Plans contain: chore descriptions, relevant files, step-by-step tasks
   - Built-in validation commands for closed-loop execution
   - Version controlled and improvable

**Anatomy of a Template**:
1. Purpose at the top
2. Detailed instructions
3. Relevant files to guide success
4. Plan format in markdown
5. A parameter that accepts your high-level description

**Higher-Order Prompts (HOPs)**: Prompts that accept other prompts as input. When you pass a plan into the implement command, you're using a HOP - plans getting passed into plans.

**The 80-20 of Agentic Coding**: With just three tactics (Stop Coding, Adopt Agent's Perspective, Template Your Engineering), you learn the Pareto principle of agentic engineering.

## Prompt 2: Framework Question (Intermediate)

**Question**: What is the R&D Framework for context engineering?

**Response**:

### The R&D Framework

> A focused agent is a performant agent. The R&D Framework provides the two-pronged approach to managing your agent's most precious resource: the context window.

**R&D = Reduce + Delegate**

| Letter | Action | Goal |
|--------|--------|------|
| **R** | Reduce | Minimize unnecessary context (50%+ reduction possible) |
| **D** | Delegate | Let agents retrieve context dynamically on-demand |

---

### Reduce: Search and Destroy Context Bloat

The real skill in context engineering is finding context agentically and then removing it. Every technique for managing context fits into Reduce or Delegate.

**Practical Reduction Tips**:
- Delete default `.mcp.json` files (they waste 10-12% of context)
- Install a token counter in your IDE
- Avoid "always-on" memory files that only grow
- Use context priming instead of bloated CLAUDE.md files

---

### Delegate: Let Agents Retrieve What They Need

Instead of pre-loading everything, let agents dynamically fetch context when they need it.

**Delegation Strategies**:
- Use `/prime` commands to load context for specific task types
- Let agents search the codebase rather than pre-loading files
- Dynamic MCP server loading with `/load-mcp`

---

### Context Engineering Levels

| Level | Skill | Description |
|-------|-------|-------------|
| 1 | Context Curator | Basic context awareness |
| 2 | Context Engineer | Active context management |
| 3 | Context Architect | System-level context design |
| 4 | (Bleeding Edge) | Advanced dynamic context systems |

**The Context Sweet Spot**: There's a range where your agent performs at maximum capability. As you scale to hundreds/thousands of agent executions, hitting this sweet spot consistently becomes critical.

**Key Warning**: If you aren't actively paying attention to context state, you're just vibe coding and can only tackle the lowest-hanging fruit.

## Prompt 3: Pattern Question (Advanced)

**Question**: What are the 7 levels of agentic prompts?

**Response**:

### The 7 Levels of Agentic Prompts

> The prompt is the fundamental unit of engineering in the age of agents. Every prompt you create becomes a force multiplier - one well-crafted prompt can generate tens to hundreds of hours of productive work.

| Level | Name | Description | Complexity |
|-------|------|-------------|------------|
| **1** | High Level Prompt | Reusable ad hoc static prompt | Lowest |
| **2** | Workflow Prompt | Sequential workflow with task list | Low |
| **3** | Control Flow | Flow control for domain-specific agents | Medium |
| **4** | Delegation Prompt | Kicks off other workflows | Medium |
| **5** | Higher Order Prompt | Prompts passing prompts | High |
| **6** | Template Meta Prompt | Prompts that create prompts | High |
| **7** | Self-Improving Prompt | Agents updating agents | Highest |

---

### Level Details

**Level 1: High Level Prompt**
- The reusable ad hoc static prompt
- One-off that you throw into a file when you start repeating work
- Contains 1-3 sections: Title and high-level prompt
- Rule: "Three times marks a pattern" → create a prompt

**Level 2: Workflow Prompt (Game Changer)**
- Huge milestone in agentic prompting
- Sequential workflow with additional sections
- The workflow section is S-tier usefulness
- A sequential list of tasks for your agent to execute

**Level 3: Control Flow**
- Building on workflow sections with flow control
- Customizable agents for domain-specific use cases
- **Key Insight**: Level 3-4 is the 80/20 for most applications

**Level 4: Delegation Prompt**
- A prompt that kicks off other workflows
- Handles delegation to multiple agents
- Properly communicates to the trifecta (you, your team, your agents)

**Level 5: Higher Order Prompts (HOPs)**
- The perfect prompt passing prompts into prompts
- Maintain the higher order prompt
- Change and swap out the lower order prompts as needed

**Level 6: Template Meta Prompt**
- A prompt used to create another prompt in a specific pattern
- Essential for advanced agentic engineering
- Meta-prompts that generate other prompts

**Level 7: Self-Improving Prompt**
- Agents updating agents through prompts updating prompts
- The highest level where the system becomes self-modifying
- Pinnacle of agentic prompt engineering

---

### The Stakeholder Trifecta

When writing prompts, you're engineering for three audiences:
1. **You** - Your own understanding
2. **Your Team** - Collaboration and handoff
3. **Your Agents** - Machine execution

## Prompt 4: Concept Question (Intermediate)

**Question**: What's the difference between the agentic layer and application layer?

**Response**:

### Agentic Layer vs Application Layer

> Tactic #8: Prioritize Agentics - More than half your engineering time should be spent on the agentic layer rather than the application layer.

---

### The Two Layers

| Layer | Contents | Focus |
|-------|----------|-------|
| **Agentic Layer** | ADWs, prompts, agents, hooks, commands, skills | Building systems that build systems |
| **Application Layer** | DevOps, infrastructure, database, app code | Traditional software development |

---

### The Agentic Layer

The "ring around your codebase" that enables autonomous operation:

```
.claude/
├── commands/       # Reusable prompts (100+)
├── agents/         # Custom agent definitions
├── hooks/          # Event-driven automation
├── skills/         # Composable capabilities
└── adws/           # AI Developer Workflows (80+)
```

**What It Contains**:
- AI developer workflow directory
- Prompts stored in `.claude/commands`
- Plans and specs
- Agent configurations
- Hook definitions

---

### The Application Layer

Traditional software components:
- DevOps configurations
- Infrastructure code
- Database schemas and migrations
- The actual application code
- APIs and services

---

### The 50%+ Rule

As a starting point, **at least half** of your engineering time should be on the agentic layer. The more you invest:

| Investment | Return |
|------------|--------|
| More time on agentic layer | More problem classes solved autonomously |
| Build the system that builds | Exponential leverage |
| Grow the "ring" | Thicker automation coverage |

---

### The Guiding Question

> "Is this work growing my agentic layer or my application layer?"

The irreplaceable engineer operates on the agentic layer much more often than the application layer.

**Minimum Viable Agentic Layer**:
1. AI developer workflow directory
2. Prompts (stored in `.claude/commands`)
3. Plans

### Core Topics Covered

#### 1. Hooks (Event-Driven Automation)

Hooks allow you to intercept and respond to agent events:

| Hook Type | Trigger | Use Case |
|-----------|---------|----------|
| `PreToolUse` | Before tool execution | Validation, security checks |
| `PostToolUse` | After tool execution | Logging, notifications |
| `Stop` | Agent completion | Cleanup, reporting |

**Key Insight**: Hooks enable "damage control" - preventing agents from taking destructive actions.

#### 2. Sub-Agents

Spawning specialized agents from within an agent:
- Break complex tasks into focused sub-tasks
- Each sub-agent has one prompt, one purpose
- Parent agent coordinates and aggregates results

#### 3. Meta-Agents

Agents that create or modify other agents:
- Self-improving systems
- Dynamic agent generation
- Agent factory patterns

---

### Key Patterns Demonstrated

1. **PreToolUse Protection**
   - Intercept dangerous operations
   - Validate before execution
   - Implement security boundaries

2. **Observability Through Hooks**
   - Log every tool call
   - Track agent behavior
   - Real-time monitoring

3. **Event-Driven Workflows**
   - Trigger actions based on agent events
   - Chain operations automatically
   - Build reactive systems
