## Part 1: Core Concepts

### What Is Overstory?
A CLI tool (`ov`) that turns a single Claude Code session into a coordinated team of autonomous worker agents. The orchestrator IS your Claude Code session — no separate daemon. Workers run in git worktrees via tmux, communicate through typed SQLite mail, and merge results through tiered conflict resolution.

## Part 2: Agent Hierarchy & Roles

### The Hierarchy
```
Orchestrator (depth 0, your Claude Code session)
  +-- Coordinator (persistent, spawned by orchestrator, no worktree)
  |     +-- Lead (depth 1, can spawn sub-workers)
  |           +-- Scout (depth 2, leaf, read-only exploration)
  |           +-- Builder (depth 2, leaf, implementation)
  |           +-- Reviewer (depth 2, leaf, read-only validation)
  |           +-- Merger (depth 2, leaf, branch merge specialist)
  +-- Direct Workers (scout/builder/reviewer for simple tasks)
```

### 9 Agent Roles

| Role | File | Depth | Capabilities |
|------|------|-------|-------------|
| Coordinator | `agents/coordinator.md` | 0 | Top-level orchestration, no worktree, dispatches work |
| Orchestrator | `agents/orchestrator.md` | 0 | Multi-repo coordinator of coordinators |
| Lead | `agents/lead.md` | 1 | Team lead, spawns sub-workers (max 5) |
| Scout | `agents/scout.md` | 2 | Read-only exploration, leaf node |
| Builder | `agents/builder.md` | 2 | Implementation, leaf node |
| Reviewer | `agents/reviewer.md` | 2 | Read-only validation, leaf node |
| Merger | `agents/merger.md` | 2 | Branch merge specialist, leaf node |
| Monitor | `agents/monitor.md` | - | Tier 2 continuous fleet patrol |
| Supervisor | `agents/supervisor.md` | - | DEPRECATED |

### Key Principle
Coordinators dispatch work and merge results. They have NO write access. Only leaf workers (builders, mergers) modify code.

## Part 3: Two-Layer Instruction System

### Layer 1: Base Definitions
Reusable `.md` files in `agents/` directory. Define HOW — workflow, constraints, capabilities, identity.

### Layer 2: Overlays
Per-task `CLAUDE.md` generated by `ov sling` and injected into the agent's git worktree. Define WHAT — task scope, file restrictions, parent agent, branch name.

The base definition is injected INTO the overlay at spawn time, so the agent sees the full instruction set without duplication.

**Template**: `templates/overlay.md.tmpl`

## Part 5: Inter-Agent Messaging (Mail System)

### 8 Message Types
- **User-facing**: `status`, `question`, `result`, `error`
- **Protocol**: `worker_done`, `merge_ready`, `dispatch`, `escalation`, `health_check`, `assign`

### Features
- **Broadcast groups**: `@all`, `@builders`, `@leads`, `@scouts`
- **Threading**: `thread_id` for message chains
- **Priorities**: `low`, `normal`, `high`, `urgent`
- **Payloads**: Optional structured JSON
- **Real-time**: `ov mail check --inject` surfaces messages in CLAUDE.md context

### Mail Commands
```bash
ov mail send --to <agent> --subject "..." --body "..."
ov mail send --to @all --subject "..." --body "..."
ov mail check                  # Check inbox
ov mail check --inject         # Surface messages into context
ov mail list                   # List all messages
```

## Part 6: Merge System (4-Tier Conflict Resolution)

| Tier | Name | Description |
|------|------|-------------|
| 1 | Clean Merge | `git merge` with no conflicts |
| 2 | Auto-resolve | Parse conflict markers, keep incoming (agent) changes |
| 3 | AI-resolve | Spawn Claude one-shot to resolve semantic conflicts |
| 4 | Reimagine | Abort merge, reimplement from scratch (disabled by default) |

### Special Handling
Auto-commits os-eco state files (`.seeds/`, `.overstory/`, `.mulch/`, `.canopy/`, `.claude/`) to prevent dirty-tree merge failures.

### Merge Commands
```bash
ov merge <branch>              # Merge specific branch
ov merge --all                 # Merge all completed branches
ov merge --queue               # Show merge queue
```

## Part 7: Watchdog (3-Tier Health Monitoring)

### Tier 0: Mechanical Daemon (default: 30s interval)
- Checks: tmux session liveness, PID existence, last activity timestamp
- Actions: warn -> nudge -> escalate -> terminate (progressive)
- Fire-and-forget: never blocks main loop

### Tier 1: AI-Assisted Triage (optional, disabled by default)
- One-shot Claude analysis of agent stdout logs
- Returns: "likely stuck in loop", "waiting for input", "needs nudge"
- Records failures to mulch for future reference

### Tier 2: Monitor Agent (optional)
- Persistent Claude Code agent with `@all` broadcast capability
- Continuous fleet patrol, escalation routing

### ZFC Principle
**Zero Fixed Configuration**: Observable state (tmux alive, PID alive) is the source of truth. The watchdog doesn't trust cached state; it checks observable reality every tick.

### AgentRuntime Interface
```typescript
interface AgentRuntime {
  id: string;
  buildSpawnCommand(opts: SpawnOpts): string;
  buildPrintCommand(prompt: string): string[];

  detectReady(paneContent: string): ReadyState;

```

### 7 Runtime Adapters

| Runtime | Instruction File | Guard Mechanism | Headless |
|---------|-----------------|-----------------|----------|
| Claude Code | `.claude/CLAUDE.md` | hooks (settings.local.json) | No (tmux) |
| Pi | `AGENTS.md` | `.pi/extensions/` | RPC |
| GitHub Copilot | N/A | `--allow-all-tools` | No |
| Codex | N/A | OS sandbox (Seatbelt/Landlock) | Yes |
| Gemini CLI | `AGENTS.md` | `--sandbox` | No |
| Sapling | N/A | `.sapling/guards.json` | RPC + NDJSON |
| OpenCode | `AGENTS.md` | N/A | Yes |

### Per-Capability Runtime Routing
```yaml
providers:
  openrouter:
    type: gateway
    baseUrl: https://openrouter.ai/api/v1
    authTokenEnv: OPENROUTER_API_KEY
models:
  builder: zai/claude-sonnet-4-6
  scout: openrouter/openai/gpt-4o
```

Scout agents (read-only) can use cheaper/lighter models. Builders get top-tier models.

## Part 12: Testing Philosophy

**Never mock what you can use for real**:
- Real filesystems: `mkdtemp()` for file I/O tests
- Real SQLite: `:memory:` or temp files
- Real git: temp repos in temp dirs
- Real subprocesses: spawned as if in prod

## Part 14: Key Design Decisions

| Decision | Rationale |
|----------|-----------|
| No separate daemon | Simplifies lifecycle. One process = one context |
| SQLite over JSON | Concurrent reads (WAL), sub-ms queries, schema flexibility |
| Strict TypeScript (no `any`) | Complex domain requires type safety |
| 3 npm runtime deps | Reduces supply chain risk, fast startup |
| Tiered watchdog | Progressive nudging before termination |
| 4-tier merge resolution | Most conflicts auto-resolve; AI for semantic conflicts |
| Instructions as Markdown | Natural language is clearer; humans read these constantly |
| Per-capability routing | Scouts don't need top-tier models; save cost |
