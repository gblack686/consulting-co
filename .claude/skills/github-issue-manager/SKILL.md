# GitHub Issue Manager

## Overview

Complete GitHub issue management system for Claude Code:
- **Post-hook** - Automatically creates issues for detected fixes
- **Agent** - Manages issues, monitors ADWs, provides analytics
- **Scripts** - Configuration, testing, and manual operations

## When to Use This Skill

Activate this skill when:
- Creating or managing GitHub issues
- Reviewing auto-generated fix reports
- Monitoring ADW workflow progress via issues
- Searching for duplicate or related issues
- Analyzing issue trends and metrics

## Quick Start

### Test Authentication
```bash
python .claude/skills/github-issue-manager/scripts/test_auth.py
```

### List Issues
```bash
# List open issues
python .claude/skills/github-issue-manager/scripts/list_issues.py

# List Claude Code fixes
python .claude/skills/github-issue-manager/scripts/list_issues.py --labels claude-code-fix

# Search issues
python .claude/skills/github-issue-manager/scripts/list_issues.py --search "authentication"
```

### Create Issue Manually
```bash
# With duplicate check
python .claude/skills/github-issue-manager/scripts/create_issue.py \
  --title "Fix: API timeout handling" \
  --type bug_fix \
  --check-duplicates

# Dry run
python .claude/skills/github-issue-manager/scripts/create_issue.py \
  --title "Test issue" \
  --dry-run
```

### Test Hook (Dry Run)
```bash
# First, enable dry_run in config
# Then simulate a fix detection:
echo '{"session_id":"test","user_message":"fix the bug","assistant_message":"I fixed the timeout issue by adding proper error handling"}' | \
  python .claude/hooks/github_issue_creator.py
```

## Hook Behavior

### Trigger Flow
1. **Stop Event** - Hook triggered when Claude finishes responding
2. **Quick Scan** - Check for fix keywords (fast, no API call)
3. **Haiku Analysis** - If keywords found, analyze with Claude Haiku
4. **Duplicate Check** - Search for similar existing issues
5. **Create Issue** - If confidence > threshold and no duplicates

### Fix Types Tracked
- `bug_fix` - Code bug corrections
- `security_fix` - Security vulnerability patches
- `edge_case_fix` - Error handling for edge cases

### Issue Template
```markdown
## Fix Applied During Claude Code Session

**Type**: Bug Fix
**Confidence**: 85%

### Description
[Haiku-generated description]

### Files Changed
- `file1.py`
- `file2.ts`

---
*Auto-generated by Claude Code GitHub Issue Hook*
```

## Configuration

### settings.json

```json
{
  "enabled": true,
  "default_repo": "gblack686/consulting-co",
  "default_labels": ["claude-code-fix"],
  "min_confidence": 0.7,
  "fix_types_to_track": ["bug_fix", "security_fix", "edge_case_fix"],
  "dry_run": false,
  "fix_keywords": ["fixed", "bug", "resolved", "patched", "security"]
}
```

### Configuration Options

| Option | Default | Description |
|--------|---------|-------------|
| `enabled` | `true` | Enable/disable hook |
| `default_repo` | `gblack686/consulting-co` | Target repository |
| `default_labels` | `["claude-code-fix"]` | Labels for new issues |
| `min_confidence` | `0.7` | Minimum Haiku confidence |
| `fix_types_to_track` | `["bug_fix", "security_fix"]` | Types to create issues for |
| `dry_run` | `false` | Log only, don't create issues |
| `fix_keywords` | `[...]` | Keywords for quick scan |

### create_issue.py

```bash
# Options
--title, -t    # Issue title (required)
--body, -b     # Issue body (markdown)
--type, -T     # Fix type: bug_fix, security_fix, enhancement, documentation
--repo, -r     # Repository (default from config)
--labels, -l   # Labels to add
--files, -f    # Files changed
--check-duplicates, -c  # Check for duplicates first
--dry-run      # Show without creating
```

### list_issues.py

```bash
# Options
--repo, -r     # Repository
--state, -s    # open, closed, all (default: open)
--labels, -l   # Filter by labels
--search, -q   # Search query
--limit, -n    # Max issues (default: 20)
--issue, -i    # Get specific issue by number
--verbose, -v  # Detailed output
--json         # JSON output
```

## Troubleshooting

### Hook Not Creating Issues

1. Check if enabled:
   ```bash
   cat .claude/skills/github-issue-manager/config/settings.json | grep enabled
   ```

2. Check logs:
   ```bash
   tail -50 ~/.claude/logs/github_issue_debug.log
   ```

3. Verify auth:
   ```bash
   gh auth status
   ```

### Authentication Errors

```bash
# Re-authenticate
gh auth login

# Check scopes
gh auth status
```

### Low Confidence Scores

- Increase `min_confidence` threshold for fewer issues
- Add more `fix_keywords` for better detection
- Check Haiku analysis in logs
