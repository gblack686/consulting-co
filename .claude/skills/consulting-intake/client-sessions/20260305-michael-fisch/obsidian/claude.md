# Fish Group — Vault Navigation Guide

This is Fish Group's AI-powered operations vault. Finn and all specialist agents use this file to navigate the vault, find information, and know where to save updates.

**Owner**: Michael Fisch + Emil Caplow
**Built by**: GBAutomation (Greg Black)
**Orchestrator**: Finn

---

## Structure

### /contacts
People connected to Fish Group. One markdown file per person or organization.

- `/contacts/team/` — Fish Group team members: Michael, Emil, future hires. Each file has role, email, GitHub handle, areas of responsibility.
- `/contacts/clients/` — Fish Group's clients (Piermont Brands, Gary's, Drop Fitness, etc.). Each file has: industry, primary contact, tech stack, agent coverage, open items, and session history.

### /agents
AI agent documentation. One file per agent in the Finn ecosystem.

- Each file describes: identity, responsibilities, skills, triggers, routing rules, cron schedule, guardrails.
- `finn.md` is the orchestrator — it routes to all other agents.
- Agent statuses: Building, Active, Phase 2 (planned).

### /workflows
Automated workflows that agents execute. Named descriptively (not numbered).

- Each file has: trigger (schedule or manual), step-by-step process, APIs used, human-in-the-loop gates, output format, prerequisites.
- Workflows reference which agent owns them.

### /projects
Active initiatives and technical work. One folder or file per project.

- Each project has: status, goal, blockers, next steps.
- Examples: Supabase migration, QuickBooks integration, OpenClaw deployment.

### /intelligence
Research, decisions, and institutional knowledge. The "memory" of the business.

- `/intelligence/decisions/` — Decision log. Each entry: date, decision, rationale, alternatives considered, outcome (updated later). **Finn should log decisions here when Michael or Emil make them.**
- `/intelligence/research/` — Market research, API evaluations, vendor comparisons.
- `/intelligence/transcripts/` — Meeting and consulting session transcripts.

### /daily
Daily operations logs in `YYYY-MM-DD.md` format.

- Morning briefs generated by Finn go here.
- End-of-day summaries, ad hoc notes, action items.
- Gives continuity across sessions — any agent can read recent dailies to understand current state.

### /resources
Reusable assets that don't belong to a specific project.

- `/resources/templates/` — Templates for client notes, daily briefs, meeting notes, workflows, agent tasks.
- `/resources/brand/` — Fish Group brand info, communication style, SOPs.
- `/resources/tools/` — Tool inventory, API credentials status, integration documentation.

### /tasks
Action items and to-do tracking.

- `blockers.md` — Current blockers requiring resolution.
- `this-week.md` — This week's priorities.
- `backlog.md` — Everything else.

## Rules for Agents

1. **When a decision is made**, log it in `/intelligence/decisions/` with date, decision, rationale, and who decided.
2. **When a new client is onboarded**, create a file in `/contacts/clients/` using the client-note template.
3. **Morning briefs** go in `/daily/YYYY-MM-DD.md`.
4. **Never auto-send emails or provision access** without Michael or Emil approval.
5. **Client isolation**: Never reference one client's data in another client's context.
6. **When updating a file**, add `updated: YYYY-MM-DD` to the frontmatter.
7. **Templates** are in `/resources/templates/` — always use them for new files.
8. **Blockers** get logged in `/tasks/blockers.md` immediately when discovered.
